# 资源显示与一键批准验收

本次检查日期为 2026-10-25（北京时间）。

## 审批流程

用户核对清单后，点击“批准并提交”。本地服务先校验内容摘要并保存批准，再创建后台提交操作。程序会上传和提交，不再要求用户返回 Codex 再次确认。面板显示“正在上传并提交”、提交失败原因或“整批已提交，可离线”。

同一批次的重复点击和 Codex 提交请求复用正在处理的操作。服务器仍按固定任务编号保证幂等。清单未批准、摘要变化或实例配置版本变化时，程序继续阻止执行。依赖安装仍需单独批准。

自动提交由本地服务执行。它不代表关闭聊天后 Codex 仍在运行或能够主动发送分析报告。用户需要进一步分析时，可以让 Codex 查询已有任务和结果。

## 采集规则

实例页面默认每 10 秒刷新，可选择 5 秒、30 秒和暂停。前端只有在实例页面可见时才请求采集。后端没有常驻资源采集定时器，关闭页面后只会完成已开始的请求。任务同步仍按原流程运行。

程序读取 CPU 计数、CPU 型号、可用逻辑核心及内存统计，并执行一次超时为 5 秒的 GPU 查询。GPU 字段包括利用率、显存、温度和功耗。缺失字段显示不可用；GPU 查询失败时，CPU 与内存仍可显示。

程序能读取 cgroup v2 的 CPU 配额和内存限制时，使用对应实例统计。否则，页面明确标记系统可见范围。CPU 百分比来自两次采样的计数差，首次采样不伪造百分比。系统重启、实例版本或 CPU 配额变化后，程序重新建立基线。

资源采集使用独立的两个工作线程，同一实例不重叠执行。多个面板共享采集结果，后端限制两次成功采集之间至少间隔 5 秒。失败后，重试间隔逐步增加，最长为五分钟。错误和旧数据的时间戳会一起保留。配置版本变化后，旧实例数据不会显示为新实例数据。

## 实测与测试

程序在已配置的真实学校实例上完成两次只读采样。两次远程采集分别耗时 45 ms 和 46 ms；包含 SSH、SFTP 辅助脚本检查与 RPC 的本地调用均约为 1844 ms。程序成功读取 CPU、内存、RTX 3080 的利用率、显存、温度和功耗。

以上数字只代表本次采集与连接耗时，不是训练性能对比。默认 10 秒适合日常观察；5 秒适合短时间查看变化。平台的网络延迟和驱动响应会影响实际开销。

86 项自动测试通过，包括一键批准自动提交、重复点击、未批准拒绝执行、CPU 计数差值、cgroup 配额、GPU 缺失字段、GPU 超时、缓存复用、失败退避、版本变化和真实 Edge 页面操作。远程脚本通过 Python 3.8 语法检查。

技术依据：[Linux 内核 /proc 文档](https://docs.kernel.org/filesystems/proc.html)和 [NVIDIA nvidia-smi 文档](https://docs.nvidia.com/deploy/nvidia-smi/index.html)。
